## Authority rule

Python alone owns worker-local model loading, adapter-only training, fixed-ticket completion and
memory measurement. C++ alone validates QLoRA certificate context, exact adapter coverage/reduce,
outer apply, ApplyQC effects and current state. Java owns content-addressed base/tokenizer caching,
opaque transport and certified adapter distribution. Python and Java cannot decide certificates,
apply state or current state; C++ does not load/train the model or infer hardware claims.

## Certificate rule

Feature 009 reuses the feature-008
`ISC → SeedTranscript → EC → APC → ParameterShardQC → AggregateRootQC → ApplyQC → current`
lineage. `QLoRAInputSetCertificate`, `QLoRAAggregateRootQC`, `QLoRAApplyQC` and equivalent parallel
types are forbidden. The QLoRA specialization is bound through training mode, base, tokenizer,
quantization, adapter schema and parent-adapter fingerprints.

## Formal and hardware boundary

The branch is `REFINEMENT_ONLY` against formal semantics
`sha256:cc98f15ac20fc3ed265cb76682ca15a936e24660a651e2b8f81638abb3265cb6` and keeps
`semantic_completeness_claimed=false`. A new action, failure terminal, durability outcome or
partial-apply transition is `SEMANTIC` and stops implementation pending a new feature-000 GO.
Without a physical runner executing the pre-frozen exact 8 GiB profile, the final decision is
`BLOCKED_HARDWARE`; offline, mock or estimated memory evidence cannot waive this gate.
