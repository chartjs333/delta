## Closure rules

1. `tasks.md` is the semantic execution ledger; `runtime-tasks.md` states non-negotiable runtime
   outcomes.
2. A task mapped to multiple obligations closes only after every mapped outcome passes.
3. An obligation spanning multiple tasks remains open until all mapped tasks and evidence pass.
4. Any accepted floating contribution, worker-selected scale, silent saturation, new rounding at a
   consensus boundary, new durability outcome or residual transaction is `SEMANTIC`: stop and
   amend feature 000.
5. P2P/Netty transport (005), hierarchy (006), robust certificates/Apply (008) and residual runtime
   cannot close a feature-004 task.
