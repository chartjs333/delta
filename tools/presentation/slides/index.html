Проблема и мотивация

Почему классический FedAvg терпит крах?

Три фундаментальных барьера на пути к безопасному федеративному обучению в недоверенной среде.

1. Византийские атаки (Poisoning)

В классическом Federated Averaging центральный координатор слепо усредняет градиенты:

wt+1 = wt + Σ (nk/n) Δwk

Злоумышленник может отправить экстремальные значения, необратимо разрушив модель («взрыв градиентов» или backdoor).

2. Недетерминизм Floating-Point

Числа с плавающей точкой (FP32/FP16) не обладают ассоциативностью сложения в IEEE-754:

(a + b) + c ≠ a + (b + c)

Разные GPU (Nvidia/AMD/Apple) и версии библиотек дают разные последние биты → разные SHA-256 хеши → консенсус невозможен!

3. Отсутствие аудита входов

Невозможно доказать третьей стороне:

  • Какие именно датасеты участвовали?
  • Не были ли отброшены валидные вклады?
  • От какого базового чекпоинта шло обучение?

DeltaReduce решает это через криптографическую фиксацию входов (ISC).

Принцип двухфазного согласования

«Сначала заморозить входы кворумом (InputSetCertificate), затем детерминированно вычислить результат, затем отдельным кворумом утвердить применение (ApplyQC)».

Последовательность фаз:

  1. Workers: Локальное обучение на изолированных приватных данных.
  2. Updates + CID: Публикация артефакта и получение контентного хеша (CID).
  3. Validators & ISC: Валидаторы кворумом фиксируют точный канонический список тикетов.
  4. Deterministic Shards: Разбиение тикетов на шарды по строгому правилу без смешивания доменов.
  5. Aggregation (QC): Сбор AggregateRootQC и финальное одобрение ApplyQC.
  6. New Checkpoint: Синхронный переход состояния у всех честных участников.

Почему одного CID недостаточно?

Один и тот же артефакт (веса) может быть предложен повторно или в другом раунде. Раунд однозначно задаётся только совокупностью: Ticket + Parent + RoundConfig + ISC.

Контекст раунда

Ticket, Родительская модель и RoundConfig

Как протокол исключает двусмысленность и подмену контекста.

🔍 Нажмите для зума

Три условия валидности заявки:

  • Родительский чекпоинт (Parent): Обязан в точности совпадать с текущим состоянием модели (например, r42). Заявка, обученная от r41, отбраковывается мгновенно.
  • Правила раунда (RoundConfig): Спецификация обучаемых слоёв (LoRA, attention), формат тензоров (размерность, dtype), схема агрегации и активный набор валидаторов.
  • Сертификат ISC: Фиксирует неизменяемый список допустимых тикетов S_r. Ни один тикет нельзя добавить после подписания ISC.
Валидация тикета:
Ticket.parent == CurrentModel.parent &&
Ticket.config_hash == RoundConfig.hash &&
Ticket.CID ∈ ISC.frozen_inputs
Теория консенсуса

Математика BFT-кворума: Почему 3f + 1 и 2f + 1?

Строгое математическое доказательство невозможности раздвоения истории.

🔍 Нажмите для зума

Теорема о пересечении кворумов

Пусть в системе допускается не более f неисправных (византийских) узлов:

Всего валидаторов: n ≥ 3f + 1
Порог кворума: q ≥ 2f + 1

Размер пересечения любых двух кворумов Q1 и Q2:

|Q1 ∩ Q2| ≥ 2q - n = 2(2f + 1) - (3f + 1) = f + 1

Поскольку скомпрометированных узлов ≤ f, в пересечении всегда есть как минимум один честный валидатор: (f + 1) - f = 1!

Следствие: защита от раскола (Fork-proof)

Честный валидатор никогда не подписывает два разных решения в одном контексте. Следовательно, два противоречивых сертификата (QC A и QC B) физически не могут одновременно собрать кворум!

Распределение шардов: Метод наибольших остатков

🔍 Нажмите для зума

Правило изоляции доменов (Domain Isolation)

В один шард никогда не смешиваются тикеты разных доменов. Число шардов: K ≥ |D|.

Разбор примера (N = 10 тикетов, K = 5 шардов):

Входы: Домен A = 8 тикетов (80%), Домен B = 2 тикета (20%).

  1. Базовое выделение: Домен A → 1 шард, Домен B → 1 шард. Остаток: 3 шарда.
  2. Идеальные доли от остатка (3):
    • Домен A: 3 × 0.8 = 2.4 (целая: 2, остаток: 0.4)
    • Домен B: 3 × 0.2 = 0.6 (целая: 0, остаток: 0.6)
  3. Распределение целых: A получает +2 шарда (итого 3), B получает +0 (итого 1).
  4. Наибольший остаток: Так как 0.6 > 0.4, последний шард уходит Домену B!
Итог: Домен A = 3 шарда, Домен B = 2 шарда.

⚠️ Исправление арифметических ошибок иллюстрации

В учебной графической схеме были допущены опечатки в вычислениях. Правильные значения:

  • Шард 1: (2×10 + 1×20 + 3×30) / (2+1+3) = 130/6 = 65/3 ≈ 21.67 (на схеме ошибочно: 20)

Целочисленная редукция (INT64)

В коде DeltaReduce агрегация выполняется не в float, а в числителях и знаменателях INT64 с фиксированным квантованием. Это гарантирует абсолютный побайтовый детерминизм на любых процессорах.

Сценарий Crash & Restart:

  1. Имитируется аварийное падение узла validator-04.
  2. Оставшиеся 3 узла формируют кворум 3 из 4 (≥ 2f + 1) и успешно продвигают раунд.
  3. При рестарте validator-04 считывает журнал упреждающей записи (Write-Ahead Log, WAL).
  4. Выполняется Replay Durable Apply Vote, и узел синхронизирует состояние без форка!
