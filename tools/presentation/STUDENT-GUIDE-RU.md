# DeltaReduce: практическое руководство для студента и профессора

**Версия руководства: 25 сентября 2026 года. Язык интерфейса: русский.**

Это маршрут знакомства с работающим приложением: понять идею, выполнить собственный эксперимент, сохранить результаты и подготовить проверяемый отчёт для профессора. Для основных сценариев достаточно браузера. Устанавливать Python, Docker или CUDA на компьютере студента не требуется: задания выполняются на компьютере, где запущено приложение.

**Текущая версия — исследовательская демонстрация.** В ней доступны реальные локальные запуски и отдельная лаборатория проверки арифметики. Полная квалификация Feature010 ещё не завершена; итогового `BenchmarkResultQC(GO)` и GO checkpoint нет. Ниже каждый сценарий объясняет свою область применимости.

## 2. Что именно вы изучаете

Главная идея DeltaReduce: несколько участников могут предлагать обновления модели, а валидаторы согласуют, **какие входы допустимы**, **как точно вычислять результат** и **какое изменение состояния можно применить**.

Концептуальная последовательность протокола:

```text
Локальные данные → обучение у воркера → артефакт обновления + ticket
    → согласование точного набора входов (ISC)
    → детерминированное распределение по доменам и шардам
    → частичные результаты → общий агрегат
    → отдельное подтверждение применения (ApplyQC)
    → следующая модель / checkpoint
```

Одинаковые канонические входы, контекст и правила должны давать одинаковый результат. Это свойство воспроизводимости и согласования. Качество модели на реальных данных проверяется отдельным научным экспериментом.

| Термин | Простое объяснение |
|---|---|
| Worker / воркер | Выполняет локальное обучение и создаёт обновление модели |
| Controller | В текущем Admin принимает задания и управляет их выполнением; его не следует автоматически считать валидатором протокола |
| Validator / валидатор | Проверяет допустимость данных и голосует в определённом контексте протокола |
| Artifact / артефакт | Данные с определённым содержимым: например, обновление или состояние модели |
| CID / content ID | Идентификатор содержимого артефакта; одного CID недостаточно для определения раунда |
| Ticket / заявка | Ссылка на артефакт с метаданными, связывающими вклад с контекстом |
| Parent | Исходная контрольная точка модели для данного раунда |
| RoundConfig | Согласованные правила раунда: схема, параметры, участники и другие ограничения |
| ISC | InputSetCertificate: сертификат согласованного набора допустимых входов |
| Domain / домен | Группа входов, которую учитывают отдельно при назначении шардов и вычислениях |
| Shard / шард | Определённая протоколом часть входов для частичного вычисления; это не обязательно файл или отдельная машина |
| QC | Quorum Certificate: сертификат решения, поддержанного необходимым кворумом |
| Receipt | В текущем обучающем примере — структурированный отчёт о локальном выполнении, связанный с заданием |
| WAL | Журнал предварительной записи, используемый native runtime для устойчивости состояния и голосов |
| Checkpoint | Зафиксированное состояние модели/протокола; обычный receipt сам по себе его не создаёт |

### Как связаны разделы приложения

В Admin работает цепочка **кампания → выбранная задача → Live execution → receipt → показ этого же запуска в Presentation**. Профиль и определения сохраняются на компьютере приложения. Статус выполнения и receipt читаются из Controller.

Лаборатория арифметики, Docker-сценарий кворума и MNIST-пример обучения узлов — **отдельные эксперименты**. Общая навигация позволяет переходить между ними, но не объединяет их результаты в доказательство одного полного протокольного запуска.

Сейчас используется общий локальный профиль, а не персональные учётные записи. Назовите свою кампанию так, чтобы её можно было отличить от чужой. Не редактируйте общий реестр контроллеров и чужие определения без согласования.

## 3. Сценарий 1 — объяснить общую идею

**Цель:** после просмотра самостоятельно объяснить путь от локального обновления до согласованного checkpoint.

Откройте [наглядное объяснение](https://expansion-raised-ends-directed.trycloudflare.com/admin/?lang=ru#/guide).

1. Пройдите все семь слайдов кнопками «Назад» и «Далее». Также доступны стрелки клавиатуры, Home/End и полноэкранный режим.
2. На слайдах об участниках найдите различие между worker, validator, артефактом и ticket.
3. Объясните, почему совпадения CID или parent недостаточно: должны совпадать контекст, правила и необходимые сертификаты.
4. Разберите пример `f = 1`: всего `3f + 1 = 4` валидатора, кворум `2f + 1 = 3`. Два таких кворума пересекаются минимум по двум участникам; при не более одном неисправном участнике среди них есть честный.
5. Прочитайте подписи и технические примечания под рисунками.

**Важная деталь:** исходные картинки на английском; русские пояснения и управление доступны рядом. В пятом рисунке есть арифметические ошибки, отмеченные в интерфейсе. Исправленные взвешенные средние: `65/3`, `12,5` и `38/3`. Условная формула `hash(ticket_id) % 3` на рисунке не является каноническим алгоритмом распределения доменов и шардов.

**Сохраните в отчёт:** собственное объяснение на 5–8 предложений и схему ролей. Рисунки служат иллюстрациями; при описании точных правил учитывайте исправления и контракты SDK/протокола.

## 4. Сценарий 2 — создать кампанию и выполнить обучение

**Цель:** получить свой результат через настоящий Controller и Python Worker, а затем найти тот же запуск в другом представлении.

### Шаг А. Подготовить эксперимент

1. Откройте [Контроллеры](https://expansion-raised-ends-directed.trycloudflare.com/admin/?lang=ru#/controllers). Найдите блок текущего исполнителя. В этой демонстрации запросы идут к подключённому локальному Controller.
2. Обратите внимание: реестр ниже документирует сведения о контроллерах. Изменение строки реестра **не переключает** исполнителя, не развёртывает узел и не создаёт независимую authority.
3. Перейдите в [Кампании](https://expansion-raised-ends-directed.trycloudflare.com/admin/?lang=ru#/campaigns).
4. Создайте кампанию, например **«Исследование студента — 25.09.2026»**. Убедитесь, что она выбрана текущей.
5. Откройте [Задачи / Workloads](https://expansion-raised-ends-directed.trycloudflare.com/admin/?lang=ru#/workloads). Выберите доступный пример с синтетическими данными и десятью признаками. Его идентификаторы:

   ```text
   model_plugin_id: tabular-10gene-phenotype-v1
   dataset_id: synthetic-10gene-cohort-v1
   ```

6. Нажмите «Использовать в кампании». Если для другой задачи написано, что она не включена в локальном Controller, не считайте наличие её описания в каталоге возможностью запуска.
7. Проверьте сохранение профиля. Сообщение «Сохранено на компьютере приложения» означает сохранение определений, а не завершение обучения.

Значки помощи возле полей раскрывают назначение, ограничения и примеры на выбранном языке. Пример в подсказке сам по себе не является введённым значением.

### Шаг Б. Запустить и проверить

1. Откройте [Live execution](https://expansion-raised-ends-directed.trycloudflare.com/admin/?lang=ru#/live-execution).
2. Проверьте выбранную кампанию и задачу в верхнем блоке.
3. Введите имя запуска, например `student_baseline_01`. Для этого поля используйте латинские буквы, цифры, `_` и `-`, до 64 символов.
4. Нажмите **«Начать обучение»** один раз.
5. Наблюдайте статус: задание принимается, ожидает Worker, выполняется и при успехе переходит в `COMPLETED`. Быстрые промежуточные статусы могут не успеть появиться на экране.
6. После подтверждения результата нажмите **«Скачать receipt»**. Откройте технические подробности и запишите идентификатор выполнения, идентификаторы модели/данных и доступные результаты.
7. Вернитесь в кампанию: запуск должен быть доступен через «Открыть статус и receipt».
8. Используйте ссылку показа этого запуска в Presentation. Сравните `execution_id`: это должен быть **тот же результат**, а не новое обучение.
9. Обновите страницу кампании и убедитесь, что ссылка на запуск сохранилась.

**Что происходит:** браузер отправляет задание Controller; отдельный Python Worker обучает небольшой классификатор на синтетических табличных данных. Интерфейс проверяет структуру receipt, его хеш и связь с запросом.

**Что сохранить:** скачанный `receipt-…json`, имя кампании, `execution_id`, дату/время, статус и снимок результата. Если итог не подтверждён или запуск завершился ошибкой, сохраните фактический статус и сообщение вместо записи «успех».

**Как интерпретировать:** это локальное выполнение плагина, режим `PLUGIN_BOUNDARY`, на CPU. Название примера с «10gene» не превращает синтетические данные в медицинское исследование. Этот путь не выдаёт ISC, ApplyQC или подтверждение записи native WAL. Карточка видимой GPU не означает, что данный запуск использовал GPU.

## 5. Сценарий 3 — проверить арифметику и защиту от подмен

**Цель:** показать не только корректный результат, но и проверяемый отказ при неправильных входах.

Откройте [лабораторию проверок](https://expansion-raised-ends-directed.trycloudflare.com/verification/?lang=ru).

1. Нажмите **«Запустить все 7 проверок»** и дождитесь завершения.
2. Изучите цепочку исходной модели, PARAMETER, преобразования координат и APPLY.
3. Для корректного закреплённого примера ожидаются:

   | Величина | Значение |
   |---|---|
   | Исходная модель | `[20, -20]` |
   | Исходное состояние optimizer | `[2, -2]` |
   | Числители результатов двух шардов PARAMETER | `1` и `-2`, знаменатели — `1` |
   | Координаты после преобразования квантов и округления | `[1, -1]` |
   | Следующая модель | `[19, -19]` |
   | Следующее состояние optimizer | `[2, -2]` |

4. Откройте «Подробности» у повторного вычисления: канонические байты вычисленных результатов должны совпасть.
5. Отдельно запустите **«Подменить байты артефакта»**. Посмотрите причину отказа: `ARTIFACT_BYTES`. Здесь содержимое действительно меняется при сохранении прежнего content ID, и эталон отклоняет несоответствие.
6. Скачайте JSON отчёта. Зафиксируйте показанный проверенный SHA-256 и отдельный хеш вычисления.
7. Повторите полный запуск. Сравните хеши **вычисления**, а не ожидайте одинаковых файлов отчёта: в отчётах различаются метаданные запусков и время.

| Проверка | Ожидаемое поведение |
|---|---|
| Корректные входы | Эталон принимает вычисленный результат |
| Повтор с теми же входами | Канонические байты результатов совпадают |
| Подмена результата PARAMETER | Отказ `ARITHMETIC_RESULT_MISMATCH` |
| Подмена следующего optimizer в APPLY | Отказ `ARITHMETIC_RESULT_MISMATCH` |
| Подмена байтов при прежнем ID | Отказ `ARTIFACT_BYTES` |
| Отсутствующий optimizer | Отказ `ARTIFACT_MISSING` |
| Другая текущая родительская модель | Отказ `PARENT_MODEL` |

**«7 из 7» означает семь ожидаемых исходов, включая отказы.** Это не семь принятых ошибочных команд. Общая схема над карточками показывает корректный базовый пример, а не результат принятия подменённого входа.

**Как работает лаборатория:** новый запуск выполняет закреплённый Python-эталон арифметики на синтетическом наборе из 12 артефактов. Проверка повтора создаёт два новых представления входов внутри одного дочернего процесса. Это не сравнение независимых native-валидаторов. Длительность на карточке относится к эталону, а не к benchmark производительности C++.

**Что сохранить:** оба JSON-отчёта, их собственные хеши, совпадающий хеш вычисления и снимок одного отрицательного случая с причиной отказа. SHA-256 подтверждает целостность, но сам по себе не является цифровой подписью или независимой аттестацией.

В JSON область применения обозначена как `FORMAL_REFERENCE_DEMO` и `SIMULATED_LOCAL`; `native_execution=false`, `gate_eligible=false`. WAL receipt, BenchmarkResultQC и GO checkpoint отсутствуют.

## 6. Сценарий 4 — увидеть обучение нескольких узлов

**Цель:** разобраться в отдельном примере распределённого обучения и сравнении поведения при отказе.

Откройте [Обучение узлов](https://expansion-raised-ends-directed.trycloudflare.com/node-training/?lang=ru).

1. Посмотрите, не отображается ли уже сохранённый результат. Это полезно для знакомства, но не означает новый запуск при открытии страницы.
2. Для собственного эксперимента нажмите **«Запустить демо»**. Дождитесь завершения до 100%.
3. Найдите четыре worker-процесса и показатели централизованного и распределённого вариантов. Запишите реальные значения с экрана.
4. Изучите показатель `BYTE-EXACT`: он относится к точному совпадению сравниваемых результатов данного примера. Отдельно запишите accuracy; точность классификации и точность совпадения байтов — разные свойства.
5. Переключите представление **«Все 4 узла»** на **«Сбой и восстановление»**. Сравните показанные результаты сценариев и сообщения о восстановлении.
6. Через верхнюю навигацию вернитесь в Admin или Presentation.

**Что происходит:** это существующий пример на MNIST с локальными процессами. Его история отделена от кампаний основного Controller; отсутствие этого запуска в вашей кампании ожидаемо.

**Что сохранить:** дату/время запуска, доступный идентификатор, метрики двух вариантов, значение `BYTE-EXACT` и снимки обычного сценария и восстановления. Подпишите, какой результат получен сейчас, а какой был загружен из истории.

**Граница:** режим `LOCAL_DEMO_ONLY`. Четыре процесса на одном компьютере не доказывают работу через реальные независимые WAN-регионы. Иллюстрация EEG использует синтетические данные, а историческая QLoRA-справка не является новым GPU-экспериментом.

## 7. Сценарий 5 — проверить кворум при отказах

**Дополнительный сценарий:** выполняйте последовательно с другими заданиями и согласуйте запуск с владельцем, если приложением одновременно пользуется кто-то ещё. На сервере должен быть готов Docker Desktop.

Откройте [Presentation](https://expansion-raised-ends-directed.trycloudflare.com/?lang=ru#overview), найдите **«Проверить кворум»** и нажмите **«Запустить сценарии в Docker»**.

Изучите последовательность в результате:

| Состояние | Наблюдение, которое нужно проверить |
|---|---|
| Доступны все четыре процесса | Собраны четыре тестовые подписи |
| Один процесс остановлен | Остаются три подписи: кворум 3 из 4 сохраняется |
| Два процесса остановлены | Двух подписей недостаточно: продвижение блокируется |
| Один из остановленных процессов возвращается | Снова возможен кворум 3 из 4 |
| Ответ старого поколения после перезапуска | Должен отклоняться проверкой поколения |

Откройте отчёт завершённого задания в [истории Presentation](https://expansion-raised-ends-directed.trycloudflare.com/?lang=ru#runs). Сохраните JSON и фактические исходы этапов. Отсутствующий или ошибочный отчёт не заменяйте ожидаемыми значениями из таблицы.

Это реальные локальные Docker-процессы и тестовые Ed25519-подписи с управляемыми остановками. Режим — `SIMULATED_LOCAL`: один компьютер и один администратор не дают независимого хранения ключей и управления. Docker bridge и доступ к странице через Cloudflare не закрывают real-WAN Gate D. Этот сценарий также не объединён с обучением из сценария 2 в единую цепочку доказательств.

## 8. Сценарий 6 — понять SDK и подготовить собственный плагин

**Цель:** дать профессору конкретную точку входа для исследовательской работы.

Откройте [SDK](https://expansion-raised-ends-directed.trycloudflare.com/admin/?lang=ru#/sdk).

1. Прочитайте «Быстрый старт».
2. Перейдите в «Источник данных»: проследите, как провайдер описывает набор данных, выдаёт обучающую партицию и отдельные данные оценки.
3. Перейдите в «Плагин модели»: найдите создание модели, обучение, схему параметров, загрузку применённого checkpoint и оценку.
4. Прочитайте «Регистрация и тесты» и «Справочник API».
5. Нажмите **«Скачать полный пример»** и сохраните `sdk_plugin_example.py` для профессора. Код можно читать и копировать прямо из браузера.

| Часть расширения | Ответственность |
|---|---|
| `DatasetProvider` | Стабильное описание данных, подготовка с учётом разрешения на скачивание, точные партиции обучения и отдельная оценочная выборка |
| `ModelPlugin` | Стабильная схема параметров, локальное обучение, загрузка параметров/checkpoint и измеряемая оценка |
| Реестры и runner | Явная регистрация совместимых компонентов и вызов их контрактов |

Учебный пример — небольшой CPU-классификатор с одним признаком, четырьмя обучающими и четырьмя отдельными оценочными примерами. Даже если он показывает 100% на этих четырёх точках, это результат учебного набора, а не оценка научного качества.

**Страница SDK не устанавливает код в работающий Controller.** Для выполнения своего плагина потребуется отдельное окружение разработки и его явная регистрация. Это следующий этап совместно с владельцем приложения. Учебный пример обозначает `LOCAL_SDK_EXAMPLE` и не выполняет консенсус.

Первое задание для обсуждения с профессором: выбрать небольшой разрешённый датасет и простую модель, зафиксировать разбиение train/evaluation, схему параметров, метрику и ожидаемую стоимость запуска. Затем реализовать `DatasetProvider` и `ModelPlugin`, проверить контракты и только после этого подключать новый workload. Для первой работы не требуется менять протокол или писать собственный механизм голосования.

## 11. Частые затруднения

| Ситуация | Что делать |
|---|---|
| Запрашивается код доступа | Получить его у владельца; это отдельный доступ к демонстрации, а не регистрация личного аккаунта |
| Туннель не открывается или показывает ошибку шлюза | Уточнить актуальный адрес и доступность компьютера приложения |
| После ввода кода появляется `ORIGIN_FORBIDDEN` | Открыть страницу заново на актуальном адресе; если повторяется, передать владельцу URL, время и текст ошибки без кода доступа |
| Страница уже показывает результат | Проверить дату и ID: возможно, загружена история; новый результат требует явного запуска |
| Выполняется другое задание | Дождаться его завершения; не открывать несколько вкладок для обхода ограничения |
| Статус недоступен или принятие задания не подтверждено | Сначала обновить статус существующего запуска; не отправлять тот же запрос вслепую повторно |
| Receipt не появился | Проверить итоговый статус и сообщение; отсутствие receipt не означает успешного завершения |
| Изменения профиля конфликтуют | Обновить данные и согласовать изменения с другим пользователем общего профиля |
| Задача есть в каталоге, но запуск недоступен | Использовать включённый синтетический пример; подключение другого плагина требует подготовки на сервере |
| Русский интерфейс, но английский рисунок или JSON | Это ожидаемо для исходных слайдов и технических данных; русские пояснения находятся рядом |
| Запуск MNIST отсутствует в кампании | Это отдельный пример со своей историей; искать его на странице обучения узлов |
