# Feature 010 benchmark operations

Feature 010 is fail-closed. A successful synthetic run or an individual runtime check is not a
primary benchmark result and cannot unblock Feature 011.

## Frozen inputs

The primary definition is `configs/benchmark/primary.yaml`. Although the extension is YAML, the
file deliberately uses the JSON subset so its bytes have one canonical representation. Its
`source_commit` is the non-evidence source commit. The companion files under `configs/benchmark/`
freeze workload, arms, model/data/evaluation revisions, licenses, metrics, WAN/fault profiles,
runtime compatibility, SBOM and evidence policy.

Regenerate those files only before any primary result exists:

```text
uv run python specs/010-wan-benchmark-and-quality/scripts/primary_contracts.py --write
```

After preregistration, changing any generated byte creates a different definition and requires a
new governance attestation and a complete rerun. Never edit a threshold to make an observed result
pass.

## Local validation

```text
uv run delta benchmark validate-definition configs/benchmark/primary.yaml
uv run delta benchmark preregister \
  configs/benchmark/primary.yaml \
  configs/benchmark/primary-definition-attestation.json \
  out/benchmark/preregistered
make benchmark-check
```

The preregistration store is create-only. Replaying identical bytes is allowed; writing different
bytes under an existing definition identity is rejected.

## Primary execution boundary

The primary control plane stages the complete mandatory arm/seed matrix only after the exact
definition attestation and environment identity have been verified:

```text
uv run delta benchmark plan-primary \
  configs/benchmark/primary.yaml \
  configs/benchmark/primary-definition-attestation.json \
  configs/benchmark/arms-v1.json \
  /approved/environment-manifest.json \
  /evidence/primary-execution
```

Planning emits `PLANNED_NOT_EXECUTED`; execution plans are not evidence. The environment manifest
must be canonical JSON and must bind the exact source commit/tree, ABI, compiler, image, JDK,
Netty, Python and dependency identities frozen by the definition.

An approved measured runner can execute the matrix through the explicit process boundary:

```text
uv run delta benchmark execute-primary \
  configs/benchmark/primary.yaml \
  configs/benchmark/primary-definition-attestation.json \
  configs/benchmark/arms-v1.json \
  /approved/environment-manifest.json \
  /evidence/primary-execution \
  --timeout-seconds 86400 -- /approved/primary-runner
```

For every plan the executor appends two arguments to the runner command: the immutable plan path
and a fresh observation-output path. The runner must write one canonical
`PRIMARY_RUN_OBSERVATION` containing the measured `RUN_MANIFEST` and metric samples, then return
zero. Identity drift, a noncanonical observation, incomplete distributed certificate evidence,
timeout, nonzero exit, or an attempted overwrite fails closed. Successfully admitted runs remain
`RUNS_ADMITTED_NOT_EVALUATED`; they do not constitute `GO` until the separate quality, exactness,
WAN/resilience, evidence, and ResultQC gates pass.

Runs produced on approved remote hosts can be ingested without re-executing them:

```text
uv run delta benchmark collect-primary \
  configs/benchmark/primary.yaml \
  configs/benchmark/primary-definition-attestation.json \
  configs/benchmark/arms-v1.json \
  /approved/environment-manifest.json \
  /evidence/primary-execution \
  /incoming/observation-*.json
```

Collection is partial and fail-closed until all plan identities exist. Require the complete,
token/domain-reconciled arm/seed inventory with `verify-primary-runs` using the same five primary
arguments. Even a complete run inventory remains `RUN_SET_COMPLETE_NOT_GATE_EVALUATED`; exact
flat/hierarchy comparison, scientific metrics, WAN/fault scenarios and the final evidence graph are
separate mandatory gates.

## Synthetic control-plane smoke

```text
uv run delta benchmark synthetic \
  delta-protocol/fixtures/010/valid/benchmark-contract-v1.json \
  out/benchmark/synthetic
```

Its output must retain `SYNTHETIC_NOT_PRIMARY_EVIDENCE`. Synthetic quality, WAN, resilience and
result attestations test the control plane only; they are never primary evidence.

## Required execution order

1. Verify the exact Feature 009 predecessor and inherited Formal GO.
2. Validate and preregister the primary definition and immutable dependency hashes/licenses.
3. Admit only exact source/build/runtime/model/data/evaluation identities.
4. Run strict C++20/C++23, Java, Python, sanitizer, durability, refinement and production-mutant
   gates.
5. Run token/domain-matched reference, flat, hierarchical, embedded and sidecar arms for every
   preregistered seed.
6. Run all emulated WAN, P2P, crash, restart, partition, churn and Byzantine scenarios.
7. Only after every emulated mandatory gate passes, run the separately approved real-WAN variant
   and record measured path conditions.
8. Verify the complete content-addressed evidence graph offline, derive one deterministic result,
   and collect the governance-only result attestation.

Any missing run, identity drift, failed mandatory gate or unavailable approved real-WAN environment
produces `NO_GO`. Benchmark attestations do not create an `ApplyQC`, do not change the current model
pointer and are outside the protocol certificate graph.

## Restricted material

Do not commit model weights, downloaded datasets, secrets or access tokens. Commit only licensed or
authorized content references, immutable revisions, hashes, manifests and measured evidence allowed
by the evidence-retention policy.
