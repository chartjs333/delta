## Deliberately unclosed source identities

The original contract context's configuration/schema/arithmetic-profile IDs,
accumulator-proof identity and original ISC/EC/APC/Q-artifact leaf identities
still lack a computed bridge to the independently anchored draft graph. The
original ROOT/QC hashes and draft aggregate IDs have different encodings. They
are retained separately, never equated or translated by a caller callback.
Shared numerical values cannot authenticate these missing source relationships.
The original native engine also accepts externally provided parent IDs; checking
their value preimages is a proposed stronger binding, not existing source behavior.

Three component counterchecks keep these limits visible: deleting metadata can
pass the value-only checker; changing accumulator identity can pass the numeric
profile comparison; removing Q leaves can pass the leaf-numbers comparison.
These do not claim that the complete structural source checker or runtime accepts
those same mutations. Full source provenance remains open even when components
are composed. No arbitrary initial snapshots, availability or phase/QC guards,
physical failure/repair, cryptographic certificate verification or public-state
refinement is inferred.

Original captures are preserved. Their label-like parent/hash identifiers cannot
be silently rewritten into computed value identities. The original arithmetic
fixture's parentCheckpoint is `parent1`, not its model value hash. A kernel case
records this incompatibility. Consequently there is NO new accepted full original
snapshot plus arithmetic plus pointer example. The generic relation is stricter;
its successful general lemmas are not a full native equivalence theorem.

Original native decimal parsing still accepts `-00` and `-01`. Exact computed
renderings are `0` and `-1`, so the new result match rejects those alternative
spellings instead of normalizing published bytes. Native decimal compatibility
remains FAIL. C++ std::to_string/from_chars and general SHA are not newly proved.
