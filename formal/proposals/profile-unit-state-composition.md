## Selected representation join

1. Admit the entire original schema-3 configuration against independent enrollment
   and that parent; check the complete S0/P0 header, original context and existing
   policy decoding without rewriting those objects.
2. Retain each original quantum-bearing canonical P byte object. The existing
   typed policy profile entry is its numeric/core field view, **not a complete P
   serializer**: it contains the original proof ID, weights, coefficients,
   Nesterov and rounding, but no quantum. Read the quantum from the original P
   bytes and check equality of the complete canonical P against all typed fields,
   the independently selected semantics and schema version 2.0.0. Hash those
   complete original bytes using the existing APPLY-profile domain.
3. Retain both the typed policy entry and the complete P bytes, its quantum and
   resulting ID in the source carrier. No typed-core re-serialization substitutes
   for P. The existing source inventory/history must bind the original P object
   to the snapshot cut; P0 alone does not authenticate this added information.
   Different quanta with identical core fields remain different P objects. Do
   not collapse them, filter unrelated inventory profiles or require every
   inventory profile to equal the currently selected configuration's numeric R.
4. Join all original APPLY candidates/QCs by those complete P IDs, using the
   existing context, root, parent, signer/quorum and collection guards. Preserve
   every other collection and all candidate/VIEW/ABORT lineage. Empty/incomplete
   collections are not replaced with a successful finalization.
5. When an APPLY is actually selected by the original producing history, derive
   its P from configuration R and the original linked APC accumulator proof;
   enforce exact P/ID equality there. Inventory membership alone is never that
   selection. A pointer step carries unchanged schema/common units, follows its
   full original QC/candidate/value preimages and preserves original journal
   lines, physical slots and multiplicity. The static join alone establishes
   neither arithmetic correctness nor authority/finality of a producing cut.

The core-field view is an internal refinement representation. The full original
bytes remain mandatory source inputs, so this does not declare the old production
policy codec capable of serializing quantum-bearing profiles or import old P
objects into the new generation. New P IDs and consequently dependent IDs arise
only from the already approved future source grammar, never by relabelling.

## Alternatives and acceptance

Rewriting every policy tree and codec to add a quantum duplicates information
already present in mandatory original P and requires a new policy wire layout.
Keeping only a core view loses units. Selecting units from current configuration
for every retained profile erases or rejects lawful unrelated inventory. The
selected paired original-bytes/core-view relation avoids all three.

The executable checker must compare entire canonical bytes before constructing
an accepted carrier; no caller-provided quantum, success flag, public projection
or desired result is a premise. Kernel soundness/completeness must preserve all
profile trees and bytes, context/configuration/parent association, collection
identities, selected profile linkage and current/journal lineage. Qualify missing,
extra, substituted, duplicate and alternate-encoding profiles, distinct quanta
with the same core, nonempty downstream collections, source/context mismatch,
empty/incomplete state and original pointer transitions. Bounds are the existing
object/native limits; add no cap or hidden source-domain restriction.

This is one part of the frozen source/state composition. Full producing history,
source/clock/seed association, complete public family and initial/incomplete/ABORT
correspondence still require composition and applicable model/refinement/review
gates. No closure or recovery theorem is inferred from a component receipt.
